# Release format

The release workflow lives in .github/workflows/release.yml. Pushing a version tag beginning with v starts six native runtime builds plus a documentation-snapshot job. The final publish job runs only after all six runtime jobs and the reference job succeed, so a failed platform prevents a partially populated formal release. Tags containing a hyphen are marked as pre-releases automatically.

## Source code downloads

GitHub automatically provides two source snapshots for every tagged release:

- Source code (zip)
- Source code (tar.gz)

These are generated by GitHub from the tagged repository tree. The CX release workflow deliberately does not upload a second, separately curated ZIP/TAR.GZ pair. These automatic source links are source snapshots, not prebuilt applications and not CX-generated packages with custom manifests.

## Version-matched reference

Each release also attaches a standalone HTML reference named CXEngine-vX.Y.Z-reference.html. It is generated from docs/reference.html in that exact tag. Links from the HTML reference to the detailed syntax, settings, project, and world guides are rewritten to the matching tag in the GitHub repository. This lets a project remain documented against the language version it was built for instead of sending every reader to the latest docs site.

The current Pages documentation site remains the main entry point and tracks the latest main-branch documentation. Older HTML references remain available as release assets.

## Native runtime packages

The runtime matrix is configured for these six native 64-bit/ARM64 targets:

| Platform | Package |
|---|---|
| Windows x86_64 | CXEngine-vX.Y.Z-windows-x86_64.zip |
| Windows ARM64 | CXEngine-vX.Y.Z-windows-arm64.zip |
| Linux x86_64 | CXEngine-vX.Y.Z-linux-x86_64.tar.gz |
| Linux ARM64 | CXEngine-vX.Y.Z-linux-arm64.tar.gz |
| macOS x86_64 | CXEngine-vX.Y.Z-macos-x86_64.zip |
| macOS ARM64 | CXEngine-vX.Y.Z-macos-arm64.zip |

No 32-bit Windows or Linux packages are configured or claimed. Adding a legacy target would require separate toolchain/dependency setup and native or equivalent runtime verification.

Each runtime package contains the graphical executable, separate CLI, a minimal editable starter project, required application runtime libraries, license notices, a first-run README, and a file-size/SHA-256 manifest. A checksum sidecar accompanies the archive. Packages intentionally exclude the development SDK: headers, static libraries, CMake metadata, and SDK documentation are not runtime dependencies. Operating-system libraries, graphics drivers, and desktop display servers are not bundled.

Windows system DLLs are filtered from both CMake's dependency-install step and the final runtime stage. This avoids copying operating-system components while retaining unrecognized application DLL dependencies. Linux packages include application libraries but still depend on the host system ABI and graphics stack. macOS runtime packages are architecture-specific.

## One project, multiple runtimes

Scripts, room JSON, configuration, and game assets remain the same across platforms. Download the runtime matching the operating system and CPU architecture; do not exchange native executables or their libraries between packages.

## Release validation and current state

Each runtime job configures and builds the graphical engine and CLI, runs CTest, checks the starter project, installs runtime dependencies, and creates the platform package. Linux jobs also perform a graphical startup smoke test under Xvfb. The regular CI workflow runs graphical startup smoke tests on Linux and Windows; automated macOS graphical startup testing is not yet included.

Both v0.10.14-preview.5 and preview.6 passed native builds, CTest, and quickstart validation on all six targets. Windows ARM64 failed during CMake's install-time dependency scan in both runs, so the publish job was correctly skipped and neither release has runtime assets. CMake lowercases Windows DLL dependency names before matching PRE_EXCLUDE_REGEXES; the first exclusion pattern used mixed-case names and therefore failed to match. The corrected filter uses lowercase exact names. Ordinary CI now runs the install-and-package path on all six native targets, and the final release job verifies all expected archives, checksum sidecars, and the version-matched reference before publishing. Create preview.7 only after that expanded CI matrix passes.
