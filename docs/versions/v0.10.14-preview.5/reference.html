How a project starts

config.json is an optional baseline. Every .cx file under scripts/ is loaded in stable path order. Top-level statements run as bootstrap; on load: is the startup event. main.cx is a convention, not a required entry point.

Use search as the index

Try on projectile hit, loop-value, random_choice, fbm2d, create light, collision, or console_enabled. Press / to focus search.

Honest feature boundaries

Important systems not implemented yet

These are design targets, not supported commands. Do not write scripts assuming they exist.

General collision response and targeting

Static tile collision has explicit per-texture defaults and per-cell room overrides, including invisible blockers; older rooms retain their previous defaults. Named trigger enter/exit events are implemented for actor/trigger entity pairs. Named-entity radius queries are implemented, but moving-entity rigid-body response, swept actor collision, line-of-sight and priority-weighted interaction policies, automatic team-based damage rules and multi-target projectile acquisition remain future work.

Advanced projectile formations

Radial/fan currently generate directions. Perimeter spawning, orbiting formations, animated transforms, independent wall/player persistence and attack timelines are not implemented.

Named animation clips

Named fixed-tick clips support fixed/facing rows, one-shot completion and looping. Blending, automatic state selection, animation import and an editor remain future work.

Programmable visual effects

v0.10.11 adds renderer-neutral textured beam quads with background/world/foreground ordering and optional independent radial endpoint lights. Bloom, shader effects, curved beams and occlusion shadows remain future work.

Physics and motion curves

Fixed-tick tweens support explicit ignore, swept stop and axis-separated slide against static tiles, room bounds and opt-in entity blockers. There is still no general rigid-body system, swept keyboard movement or dynamic moving-obstacle solver.

Audio mixer

Wave generation/export and optional playback exist. Realtime buses, voice management, automation, robust device handling and VST hosting are not implemented.

Design direction: the target is a high-performance 2D action/bullet-hell engine with batched geometry, pooled effects, low-resolution glow compositing, explicit collision filters and deterministic pattern math. This reference will label each new feature only after its implementation and tests exist.
