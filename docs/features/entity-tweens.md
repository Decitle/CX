# Deterministic entity tweens — v0.10.5

CX v0.10.5 adds a small fixed-tick movement primitive for scripted entity motion and a one-shot completion event.

## Start a tween

```cx
create entity "boulder" with texture {$stone}
set entity "boulder" position to (180, 440)

tween entity "boulder" to (700, 360) over 0.9 seconds easing ease_in_out with arc height 120
```

A tween moves the entity's top-left position between its captured starting point and the destination. Coordinates use world pixels. `seconds` is evaluated when the command runs and converted to a fixed tick count using the engine tick rate at that moment. The tick count is rounded up, so a duration shorter than one tick still takes one tick. Changing the tick rate afterward does not change the active tween's tick count.

Supported easing modes are:

- `linear`: constant interpolation progress.
- `ease_in`: starts slowly and accelerates (`t²`).
- `ease_out`: starts quickly and decelerates (`1 - (1-t)²`).
- `ease_in_out`: symmetric smooth acceleration/deceleration.

The optional `with arc height N` adds a parabolic upward offset above the straight interpolated line. The arc reaches its requested height halfway through the tween and returns to zero at the endpoints. Positive height moves upward on screen (toward smaller Y coordinates). Omit it for straight-line motion.

## Completion event

```cx
on tween complete for entity "boulder":
    set {boulder_arrived_x} to {_tween_x}
    set {boulder_arrived_y} to {_tween_y}
    set {boulder_name} to {_tween_entity}
```

The handler runs once after the entity reaches the exact destination. All handlers for the same completion receive the captured arrival coordinates, even if an earlier handler moves the entity. Its local values are `{_tween_entity}`, `{_tween_x}`, and `{_tween_y}`. Multiple handlers for the same entity run in script order while the same entity instance and room context remain valid. If a callback deletes or replaces that entity, later handlers for the old instance are skipped.

## Cancellation and ownership

```cx
cancel tween for entity "boulder"
```

Cancellation is silent and does not dispatch completion. Starting a new tween for the same entity replaces the active tween without completing the old one. Setting the entity's position, moving it manually, moving it with pressed directional input, assigning a tile path, deleting it, or replacing it with a new object cancels the previous tween. Starting a tween clears its existing tile path and navigation state. A room-context transition discards old-context tweens without completion; startup tweens created during a successful transactional script load are kept and rebased to the newly committed room context.

## Deliberate limits

- This is deterministic position interpolation, not a physics body, velocity, impulse, spring, or collision solver.
- It does not test or avoid solid tiles, actors, props, hazards, or triggers. It can move through walls. Use input/path movement for the existing tile-avoidance behavior, or script a route explicitly.
- It affects only one named ordinary entity at a time. Projectiles and plain sprites are not tween targets.
- There is no pause/reverse/seek API, per-frame callback, relative target, path spline, or animation clip integration yet.
- No text, dialogue, interaction prompt, or other player-facing content is generated by the runtime. The script remains responsible for all authored words and interaction design.

The focused test executable is `cx-motion-tests`. It covers the easing curves, arc midpoint, exact destination, completion locals and one-shot behavior, replacement, cancellation, manual movement, same-name instance replacement, callback deletion, invalid duration/arc rejection without disturbing an active tween, and room-context invalidation.
